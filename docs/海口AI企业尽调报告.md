## 一、总体结论

原表格存在的不是"信息不全"的问题，而是**结构性失真**：薪资普遍虚高一档、区域随意标注、业务描述与工商登记的经营范围对不上、部分企业名称在工商系统中查无对应主体。

按可信度分四档：

| 档位 | 数量 | 说明 |
|---|---|---|
| A 真实可靠，有真实 AI 岗位 | 6 家 | 主体可查、有规模、在招岗位真实 |
| B 主体真实，但业务/区域/薪资描述失实 | 9 家 | 公司存在，但与表格描述不是一回事 |
| C 实际规模极小（2–12 人） | 4 家 | 真实存在，但撑不起表格写的业务与薪资 |
| D 查无此企或名称对不上 | 7 家 | 无法在工商系统找到对应主体 |

**最具操作性的结论：全表 28 家，真正在招 AI 相关岗位且值得前端转行者投递的，不超过 6 家。** 其余多为销售、交付、运维岗，或规模不足以支撑表格描述的业务。

## 三、这张表本身的三个硬伤

1. **薪资系统性虚高。** 全表薪资区间高度规律（10–32K 连续递进、统一 13 薪），但可核实的实际挂牌薪资是：百度海口标注岗 3–8K、中广指南针 6–10K、卓世科技交付岗 10–20K、海控数科交付岗 8–18K。**表格写的下限普遍等于甚至高于这些公司真实岗位的上限。**

2. **区域标注随意。** 至少 5 家区域标错：壹联（实际三亚，写美兰区）、智算云擎（实际澄迈，写高新区）、椰云（实际澄迈，写龙华区）、智海（实际三亚或复兴城，写美兰区）、腾讯（无海南主体，写复兴城）。

3. **岗位内容跨行业复制粘贴。** 小蝇科技是医疗血液形态学 AI，表格却给它配"GIS-AI 应用开发、空间 Agent 研发"；星智数字是短视频方向，岗位写"工控 AI 应用开发"。"内容 RAG 工程师""业务 Agent 研发"等表述在多家重复出现。

### 2. 前端转 Agent 的三条可行路径

**路径 A：Agent 应用层前端（最贴近现有经验）**
对话工作台、流式输出（SSE/WebSocket）、工具调用过程可视化、多轮会话状态管理、知识库管理后台。技术栈：React/Vue + TypeScript + SSE + 状态持久化。这条路你的 6 年前端经验是直接资产，不用从零学 Python。

**路径 B：TypeScript 全链路（过渡最平滑）**
LangChain.js / LlamaIndex.TS 搭 RAG 与 Agent 编排，Node BFF 层做工具调用与鉴权，pgvector 做向量检索。整条链路只用 TS，你现有的 monorepo 和工程化能力可直接复用，同时把"RAG/Agent"写进履历。

**路径 C：Python 侧补齐（天花板最高）**
Python + LangChain/LlamaIndex + FastAPI + Milvus/pgvector，配合 Dify/Coze 的私有化部署与二次开发。这条需要 2–3 个月投入，但能投研发岗而非交付岗。

**建议组合：主攻 A，用 B 落地作品，同步补 C 的基础。** 手上要有 1–2 个能演示的 Agent 项目（比如把你在做的 Vue 面试学习应用改造成带 RAG 知识库 + 多轮工具调用的 Agent 产品），这比简历上的关键词管用得多。

### 3. 三个必须避开的坑

- **别信"内推机构统一整理的汇总表"。** 本次核查已证明其失真比例极高，用这种表投简历等于把时间浪费在查无此企的公司上。
- **必须问清薪资结构。** 海口本地"XX–XXK·13 薪"通常取下限，且很可能是"底薪 + 绩效"结构，13 薪是否写进合同要确认。
- **海口 AI 岗位的结构性现实：** 本地真正做 AI 研发的团队少，销售、交付、运维岗位占多数。若目标是做 Agent 研发，需要同时考虑一线城市岗位或远程岗位，"海口 + AI 研发"的岗位池确实很浅。

## 五、自己核验一家公司的四步法

1. **查参保人数**（企查查/爱企查 → 工商信息）：< 5 人基本是空壳或办事处；< 20 人撑不起"大模型研发"叙事。
2. **查注册地址**：注册在酒店房间号、共享办公工位（如"XX 大厦 18 楼 1803-1804 房 96 室"）、住宅小区房，基本都是极小团队。
3. **查成立时间**：2025–2026 年新成立的公司，业务描述再漂亮也要打折，"本土明星企业"这类头衔尤其要警惕。
4. **反查真实岗位**：在公司官网招聘页、BOSS 直聘、猎聘、职友集上搜公司名，看它在招什么、给多少钱——**招聘平台上挂的薪资比宣传册上的可信十倍。**
