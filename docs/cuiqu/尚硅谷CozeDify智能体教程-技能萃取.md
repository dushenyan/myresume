## 1. 核心技能清单（含子技术拆解）

### 技能 1：RAG 知识库工程

| 子技术 | 说明 | 教程中的体现 | 解决什么问题 |
|--------|------|------------|------------|
| RAG 检索-增强-生成原理 | 文档加载 → 切分 → 向量化 → 召回 → 重排 → 注入提示词 → 生成 | 15 步执行流程详解（RAG 架构图） | LLM 知识时效与私有数据缺失 |
| 三类模型使用点 | 向量化用 EmbeddingModel、重排用 RerankModel、生成用 LLM | 流程第 3/7/9 步标注 | 知道 RAG 各环节选什么模型 |
| Reranker 精排 | 对 top 20~50 初召回 chunk 精排，提高准确率 | 适用场景分析 | 无关信息干扰 LLM、成本时间 |
| Reranker 取舍边界 | 高精度场景（专业库/客服）适合；高响应要求场景不适合（延迟+成本） | 笔记对比分析 | 检索精度 vs 延迟的工程权衡 |
| 知识库平台选型 | Cherry-Studio / ima（微信生态）/ Dify 三平台对比 | 搭建过程全流程记录 | 不同规模场景的工具选型 |
| 源数据格式处理 | 知识库支持的文档类型与预处理 | Dify 源数据格式章节 | 原始资料入库规范化 |

**简历关键词**：`RAG` `Embedding` `Rerank` `知识库` `检索增强`

### 3.4 面试弹药（简历不写，被问必答）

- Reranker 什么时候值得加？（高精度场景如专业库/客服；高响应要求场景不加——延迟+成本）
- 短期 vs 长期记忆怎么实现？（短期=上下文窗口；长期=微调固化/知识图谱/向量库三路径）
- Agent 三 Level 怎么选？（简单人设用提示词；固定流程用工作流；需要自主规划才上高阶）
- Coze 和 Dify 怎么选？（Coze 生态集成强 / Dify 开源可私有化）
- 代码节点的输入输出机制？（`args` 注入参数、`ret` 返回对象）
- SSE 和 WebSocket 的区别？（SSE 单向服务器推送、HTTP 友好；WebSocket 双向）
