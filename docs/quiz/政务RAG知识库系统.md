## 预测押题

- 为什么政务政策场景纯向量 RAG 不行？GraphRAG 的多跳推理入口具体指什么？
  政策条款互相引用（「按第 X 条执行」「第 X 条除外」），问 A 政策需要 B 文件的上下文，但 B 与问题语义相似度低，纯向量召不回。图谱存「文档—条款—主题」关系边，沿边取 N 跳关联条款，这就是多跳推理入口。
- MySQL + Elasticsearch + Neo4j 三存储异构架构，每份数据存几份？一致性怎么保证？
  职责分离不重复存内容：MySQL 是业务元数据与原文的 source of truth，ES 只存全文/向量索引，Neo4j 只存实体关系。写入成功后同步/异步分发更新另两库，定时对账任务兜底补偿。
- 图谱构建的实体关系从哪来？政策文件更新后图谱怎么增量维护？
  规则（条款编号、引用句式）+ LLM 抽取三元组，人工抽检校验。文件更新时以文档 ID 为界删旧边、重抽取、写新边，幂等可重跑，不动无关子图。
- 两阶段检索「召回求快、精排求准」具体怎么分工？bge-reranker 交叉编码为什么慢？
  召回用混合检索（BM25+向量）从全库快速取 top 几十条；精排用 bge-reranker 对 (query, chunk) 逐对打分取 top-5。交叉编码 query 与文档拼接过完整 Transformer，无法预计算向量，每 query 都要 N 次前向，所以慢但准。
- Rerank 引入时机的业务权衡是什么？哪些场景你明确决定不用精排？
  政策答复等高精度场景强制精排（错答代价大于延迟）；通用闲聊/导览场景只用混合检索，省掉精排的延迟与算力。判断标准是场景 SLA 与错答代价，不是技术默认值。
- 重叠分块的重叠窗口怎么定？分块策略迭代靠什么指标驱动？
  窗口取 chunk 长度的 10%～20%，保证跨块的条款引用、表格表头不被切断。迭代靠评估集的 Top-5 召回率与 faithfulness 指标驱动，改策略跑回归看数字。
- RAGAS 的 faithfulness / answer relevancy / context precision 分别衡量什么？评估集怎么构建？
  faithfulness 看回答是否被召回上下文支撑（幻觉维度）；answer relevancy 看回答与问题相关性；context precision 看召回内容里有用信息的占比与序。评估集从真实高频咨询采样 + 人工标注黄金上下文构建。
- Top-5 召回率 71% 到 93%，主要贡献来自哪几个改动？怎么归因？
  大头是图谱多跳补全跨文档上下文与 rerank 提精，再加分块策略修正断句问题。归因方法：同一评估集上逐策略开关跑回归（ablation），看每个改动单独带来的增量。
- 回答如何溯源到政策原文与图表？Chunk 元数据里持久化了什么？
  pdfplumber 解析版面时按重叠窗口智能分块，chunk 元数据记录页码、章节、关联图表文件路径，前端据此把回答精准定位到原始政务图表与原文页，形成可解释闭环。
- embedding / rerank 模型为什么模块级单例？私有化部署算力受限怎么办（vLLM/XInference）？
  权重数 GB，每请求加载会内存爆炸且延迟秒级起步，所以启动时加载一次全局共享。生成侧大模型经 XInference（vLLM 后端）服务化接入，吞吐高且数据不出域；embedding 支持 cuda/mps/cpu 自适应降级。

## 项目亮点挖掘

1. **三存储异构架构**
   MySQL 业务元数据 + ES 全文向量双路 + Neo4j 实体关系图谱，图文协同检索打通跨文档隐式关联。
2. **两阶段检索 + 场景化 Rerank**
   混合召回 + bge-reranker 精排；政策答复强制精排、通用对话仅混合检索，延迟与命中率按场景平衡。
3. **RAGAS 版本化回归**
   faithfulness ≥ 0.92、Top-5 召回率 71%→93%，HITL 反馈闭环驱动分块与精排策略迭代，调优可量化可归因。
4. **可解释溯源闭环**
   pdfplumber 重叠窗口版面分块，Chunk 元数据持久化页码与关联图表路径，回答精准溯源至原始政务图表。
5. **模型服务化部署**
   模块级单例加载避免每请求重复加载数 GB 权重；XInference（vLLM 后端）服务化，cuda/mps/cpu 自适应。
