## 预测押题

- 为什么用辩论式多 Agent 而不是单个 Agent 直接给决策建议？多 Agent 的成本怎么对得起收益？
  单 Agent 有自我确认偏差：一次生成把先输出的立场合理化到底，看不到对立面。辩论把两个立场强制对抗，决策价值在于知道「放弃了什么」。成本一场 ~11 次调用，只用在高代价决策（选方案/取舍）上，日常问答用不着。
- 辩论的哪个环节对决策质量贡献最大？如果预算只够一半调用次数，砍哪个阶段？
  质询-反驳环节贡献最大（暴露对方论据的隐含假设，立论只是把已知说一遍）。预算减半会砍总结陈词（信息增量最低）并把反驳限为一轮，保留立论+质询+裁决骨架。
- 法官也是 LLM，会不会被辩方话术带偏？怎么提高裁决可靠性？
  会，尤其被自信表达和长文带偏。对策：四维评分量规逐项打分而非整体印象分；要求每个分数附证据引用；裁决顺序在双方陈述之后独立进行；分差小于阈值不硬判转人工——承认 LLM 法官的局限而不是假装它中立。
- 多 Agent 辩论最容易出现什么问题？你怎么防共识坍缩？
  最常见坍缩：双方越辩越客气互相让步直至合流。双层防御：Prompt 层严禁认同对方立场（角色锁定）；编排层在每阶段后用让步话术检测扫描输出，命中即判定坍缩——不信任模型自觉，用外部监控兜底。
- 让步话术检测的关键词是怎么定的？漏检和误杀怎么平衡？
  从真实坍缩样本归纳（「对方说得有道理」「我方承认」「确实如此」类句式），按让步断言而非普通连接词匹配。平衡：宁可误杀（中止代价低、可重跑）不可漏检（假共识直接污染决策）；误杀率用历史辩论集回归控制。
- 检测到坍缩后为什么是中止而不是继续跑完？用户侧怎么处理？
  坍缩后的后续阶段输入已被「假共识」污染，继续跑只会得出包装过的垃圾结论，不如省钱早停。用户侧：明确标记本场结果不可信 + 原因，提示重新发起或转人工，绝不静默降级。
- 辩论什么时候该结束？你的终止条件是怎么设计的？
  三重终止：固定轮数上限（成本兜底）、共识坍缩早停（质量兜底）、分差达阈值提前定论（收益兜底）。单靠轮数会烧钱在已分胜负的局上，单靠分差会被早期假分差骗，三个条件互补。
- 分差阈值（WIN_MARGIN）怎么定？为什么分差小要转人工而不是硬选一个？
  用历史场次分差分布标定：小于阈值的局人工复判多数也无明显优劣，硬判等于把噪声包装成结论。转人工把不确定性如实交给用户，附双方完整论据供其判断——系统的诚实比假装果断重要。
- 反驳轮数越多越好吗？怎么权衡质量与成本？
  不是，边际收益递减：第二轮后多为重复观点加措辞修饰，成本却线性涨。实测 1-2 轮反驳后观点覆盖率已平，上限设固定轮数，配合分差提前终止控制成本。
- 辩论过程怎么可视化？WebSocket 的事件流是怎么实现的？这套架构怎么扩展到多方（>2）辩论？
  每阶段产出以事件（阶段名/角色/内容/评分）经 WebSocket 逐条推送，前端渲染时间线 + ASCII 评分条，用户实时看进展而非等总结果。多方扩展：图结构从双方对抗改多角色轮辩，法官不变；主要改终止条件（两两分差矩阵）与发言调度，坍缩检测要升级为联盟化检测。

## 项目亮点挖掘

1. **结构化辩论决策**
   立论→质询→反驳→总结→裁决，让对立观点在规则下对抗，避免单 Agent 自我确认。
2. **双层防共识坍缩**
   Prompt 严禁认同 + 编排层让步话术检测，命中即中止并标记结果不可信。
3. **法官四维加权裁决**
   论据质量 0.35/逻辑严密 0.25/反驳效力 0.25/表达清晰 0.15，决策可解释。
4. **三重终止条件**
   固定轮数、共识坍缩早停、分差阈值转人工，成本和置信度双可控。
5. **WebSocket 实时可视化**
   每阶段事件流逐条推送，前端可直接渲染辩论过程与 ASCII 评分条。
6. **实测正方 85.5 vs 反方 80.0**
   分差 5.5≥WIN_MARGIN=5，判明确胜出；每场 11 阶段事件全产出。
