**项目详情**

**精选**

MCP 工具服务器集合

Python 3.9+ | FastAPI | SQLite | Docker

**技术文档说明**

**项目概述**

实现 3 个 MCP (Model Context Protocol) 服务器：文件系统 / SQLite / 企业 API 网关，完整覆盖 MCP 三大原语 (tools / resources / prompts)，内置路径白名单 + 只读模式 + SQL 守卫 + Token 鉴权四道安全防线。解决 LLM 应用需要标准化工具接入协议、且文件/数据库/企业 API 暴露给模型必须安全可控的问题。

**核心技术架构**

项目采用“HTTP JSON-RPC 传输层 → MCP 协议核心 → 业务 Server”的三层架构。

【MCP 协议核心】：自研轻量 mcp_core.py，实现 JSON-RPC 2.0 分发 + initialize 能力协商 + 结构化错误码体系（-32001 越权 / -32011 SQL 守卫 / -32602 参数错误），响应层永不抛异常。

【三原语实现】：每个 Server 同时注册 tools（模型可调用的动作）、resources（URI 寻址的上下文数据）、prompts（预置提示词模板），initialize 返回 capabilities 能力声明。

【文件系统 Server】：list_dir / read_file / write_file 三工具 + file:// 资源 + 目录分析 prompt；realpath 白名单防 ../ 目录穿越与软链逃逸 + 只读开关 + 64KB 读取上限。

【SQLite Server】：query 仅放行 SELECT、正则拦截 DROP/DELETE/UPDATE/INSERT/ALTER/CREATE/ATTACH 7 类危险关键字、fetchmany(100) 限制结果集。

【企业网关 Server】：把内部 HR/项目系统包装为 MCP 工具，下游 service-token 由网关代持注入，客户端永远接触不到内部凭证。

【鉴权】：传输层 X-API-Token 统一校验，无 token 返回 401；企业网关再做下游凭证隔离。

【服务化】：FastAPI 端口 8200，POST /mcp/{server_name}；Dockerfile 支持一键容器化部署。

**项目亮点挖掘**

   tools/resources/prompts 每个 Server 全注册，协议版本 2024-11-05。

辩论式决策多 Agent

Python 3.9+ | FastAPI | WebSocket | OpenAI 兼容协议

**技术文档说明**

**项目概述**

用“结构化辩论”做决策的多 Agent 系统：正反双方立论-质询-反驳-总结，法官按四维度打分裁决，双层防共识坍缩，WebSocket 实时可视化。解决单 Agent 决策视角单一、自我确认的问题，让对立观点在规则下对抗并由独立裁判定裁决。

**核心技术架构**

项目采用“立论 → 质询 → 反驳 → 总结 → 法官裁决”的结构化辩论流水线。

【结构化辩论流程】：正方/反方/法官三类 Agent 按“立论×2 → 质询×2 → 反驳×N 轮 → 总结×2 → 法官裁决”推进，每阶段产出结构化 JSON。

【防共识坍缩】：第一层在 Prompt 层严禁辩手认同对方、强制从论据质量切入反驳；第二层在编排层检测“我方认同/对方说得对”等让步话术，命中即中止辩论并标记结果不可信（aborted）。

【法官四维评分】：论据质量 0.35 / 逻辑严密 0.25 / 反驳效力 0.25 / 表达清晰 0.15，评分依据论据与反驳效力不看辞藻。

【终止条件】：三重设计——固定反驳轮数保证成本上界、共识坍缩提前终止止损、分差阈值 WIN_MARGIN=5 区分 decided（明确胜出）/ close_call（势均力敌需人工）/ aborted（坍缩不可信）。

【可视化】：每阶段产出结构化事件流，WebSocket 逐阶段实时推送（后台线程 + asyncio 队列桥接），前端可直接渲染辩论过程与 ASCII 评分条。

【服务化】：FastAPI 端口 8150，提供 /debate 与 /ws/debate 接口。

**项目亮点挖掘**

1. **结构化辩论决策**
   立论→质询→反驳→总结→裁决，让对立观点在规则下对抗，避免单 Agent 自我确认。
2. **双层防共识坍缩**
   Prompt 严禁认同 + 编排层让步话术检测，命中即中止并标记结果不可信。
3. **法官四维加权裁决**
   论据质量 0.35/逻辑严密 0.25/反驳效力 0.25/表达清晰 0.15，决策可解释。
4. **三重终止条件**
   固定轮数、共识坍缩早停、分差阈值转人工，成本和置信度双可控。
5. **WebSocket 实时可视化**
   每阶段事件流逐条推送，前端可直接渲染辩论过程与 ASCII 评分条。
6. **实测正方 85.5 vs 反方 80.0**
   分差 5.5≥WIN_MARGIN=5，判明确胜出；每场 11 阶段事件全产出。

多租户知识库问答 Agent

Java 17 | Spring Boot 3.3.5 | Spring AI（生产） | Milvus（生产） | PostgreSQL / Redis（生产）

**技术文档说明**

**项目概述**

多租户文档入库 → 向量库分区（物理隔离）→ 文档级 ACL 过滤召回（元数据隔离）→ 防泄漏后置校验 → 带引用问答 → 审计流水与计费。SaaS 知识库纵深防御架构，确保“绝不能让 A 公司检索到 B 公司的文档”。

**核心技术架构**

项目采用“租户上下文 → 分区召回 → ACL 过滤 → 防泄漏后置校验 → LLM 问答 → 审计计费”的多租户知识库问答流水线。

【租户上下文】：强制非空构造（禁止匿名检索），租户标识由 API 网关鉴权后注入 X-Tenant-Id 头，应用层不信任客户端自报租户。

【分区向量库】：按 tenantId 分区存储/检索（Milvus partition 等价），检索只扫本租户分区，跨租户数据在数据结构层面不可达。

【权限检索器】：三层防线——分区召回 → 文档级 ACL 过滤（候选多取 topK×3 再过滤）→ 防泄漏后置校验（逐条断言 chunk.tenantId == 请求租户，不一致即熔断）。

【问答流水线】：检索 → LLM 生成（MockLlmGateway / SpringAiLlmGateway 接口对齐）→ 审计落账。

【审计计费】：每次问答落审计流水（租户/用户/问题/命中数/token 估算/拦截原因），按租户聚合计费 + 安全巡检（被拦截访问清单）。

【REST 接口】：端口 8100，/ask /audit /billing（X-Tenant-Id / X-User 头注入）。

**项目亮点挖掘**

1. **双重隔离**
   向量库按 tenantId 分区物理隔离 + chunk 级 ACL 元数据过滤，跨租户数据在结构层面不可达。
2. **防泄密纵深防御**
   返回前逐条断言租户一致性，不一致立即熔断抛异常并记 BLOCKED_TENANT 审计，即使上游逻辑改坏也不泄漏。
3. **权限过滤召回策略**
   候选多取 topK×3 再 ACL 过滤，避免过滤后不足数；过滤为空时明确提示“有 N 条命中因权限被过滤”。
4. **问答审计与计费**
   每次问答落审计流水，按租户聚合计费 + 安全巡检，SaaS 商业化合规有据。
5. **租户身份安全设计**
   TenantContext 强制非空构造，租户头由网关鉴权后注入，应用层不信任客户端自报。
6. **LLM 网关接口化**
   Mock/SpringAI 双实现接口对齐，核心隔离链路纯 JDK 可离线编译验证。

DevOps 运维诊断 Agent

Python 3.9+ | FastAPI 0.115 + Uvicorn | OpenAI 兼容协议 | Prometheus / ELK / K8s API（预留，演示用 MockCollector）

**技术文档说明**

**项目概述**

告警触发自动诊断：查指标、检索日志、分析 K8s 事件、定位根因，ReAct 观察-假设-验证循环 + HITL 安全处置。解决线上故障排查依赖资深 SRE 人肉串联“指标-日志-变更”三类证据，响应慢且经验难沉淀的问题。

**核心技术架构**

项目采用“告警接入 → 证据采集 → ReAct 诊断 → 修复方案 + 风险评估 → HITL 安全处置 → 准确率评估”的完整运维诊断流水线。

【告警接入】：P1-P3 分级映射 + 同源告警 300s 窗口去重 + 按服务聚合关联，一波 4 条告警收敛为 1 次诊断。

【证据采集】：日志/指标/K8s 事件/变更四类证据源，Mock 注入“发布后连接池泄漏”确定性故障场景。

【诊断引擎】：ReAct 循环（观察-假设-验证-结论），规则引擎 4 条阈值规则（CPU>85% / 5xx>5% / DB P99>500ms / 连接池满），历史案例库召回 + LLM 假设，LLM 调度工具逐轮取证（上限 MAX_VERIFY_ROUNDS=3 防死循环），DiagnosisEvaluator 准确率评估（≥80 记命中，实测 92/100）。

【处置层】：修复方案生成 + LLM 风险评估 + HITL 关卡（高危操作无确认一律拦截）+ 模拟执行（失败自动回滚）。变更关联窗口 CHANGE_WINDOW_MIN=60min。

【流水线 + 服务】：编排 + Markdown 诊断报告渲染，FastAPI 端口 8060。

教育个性化辅导 Agent

**技术文档说明**

**项目概述**
学生答题 → 画像实时更新（知识点掌握度向量）→ 按薄弱点+难度选题 → 答错苏格拉底式引导（不直接给答案）→ 错因三类归因 → 连对升/答错降的动态难度。解决 K12 辅导中题海战术无差别推送和直接给答案剥夺思考的核心矛盾。

**核心技术架构**
项目采用“学生答题 → 判题 → 画像更新 → 薄弱点排序 → 动态难度选题 → 答错引导/归因”的个性化辅导闭环。

【学生画像】：以“知识点掌握度向量”建模学生能力，冷启动先验值 COLD\_START\_MASTERY=0.5，每次答题指数平滑更新（mastery=(1-α)·old+α·表现，MASTERY\_ALPHA=0.3），兼顾近期表现与历史积累。

【题库】：3 知识点 × L1-L3 难度结构化题目，答案归一化判题（全角/空格容错），难度档耗尽自动就近降档兜底。

【辅导引擎】：优先选掌握度最低的薄弱知识点出题，连续答对 PROMOTE\_STREAK=2 题升档、答错降档（MAX\_LEVEL=3 / MIN\_LEVEL=1），已出题去重防重复刷。

【苏格拉底式引导】：答错时 LLM 只做启发式提问，Prompt 层严禁直接给出答案；错因三类归因（概念不清/粗心失误/方法错误）并给出针对性练习建议。

【HTTP 服务】：FastAPI 端口 8080，支持按画像选题、提交答案、查询学生画像。

**项目亮点挖掘**

1. **学生能力画像模型**
知识点掌握度向量 + 冷启动先验 0.5 + 指数平滑更新（α=0.3），单题失误打不崩画像。

2. **苏格拉底式引导防答案泄漏**
Prompt 层显式禁令 + 输出形态约束为提问句 + 信息隔离（标准答案不传给引导 Prompt）。

3. **动态难度调整落在“最近发展区”**
连对 2 题升档、答错降档（保底 L1），薄弱知识点优先选题。

4. **错因三类归因**
概念不清/粗心失误/方法错误，给出针对性练习路径（如“先练 3 道通分专项再回分数加法”）。

5. **画像可解释可运营**
掌握度、答题数、正确数三本账，薄弱知识点自动排序输出。

6. **题库结构化设计**
知识点 × L1-L3 难度 × 考查技能三元组建模，全链路离线可运行。
