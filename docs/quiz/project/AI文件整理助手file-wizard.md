## 预测押题

- 你说「手写 MCP 客户端协议层」，具体实现了协议的哪些部分？为什么不用现成 SDK？
  实现 JSON-RPC 2.0 消息帧、initialize 握手、tools/list、tools/call 与 server 进程管理。不用 SDK：当时 TS SDK 生态未稳定，且只需客户端子集；自研 300 行量级换来超时/错误码/日志完全可控，协议升级自己改。
- initialize 握手和能力协商在客户端侧做了什么？tools/list 发现到 tools/call 调用的完整链路讲一下。
  客户端发 initialize（协议版本 + 自身能力）→ 收 server 能力声明 → 发 initialized 通知；之后 tools/list 拉工具清单（支持分页）拼进模型工具参数，模型返回调用意图后 tools/call 执行并回填结果，形成 Tool Use 闭环。
- MCP server 进程是怎么拉起和管理的？进程异常退出、stdio 断流怎么处理？
  spawn 子进程持有 stdin/stdout 管道，请求带 id 匹配响应。退出码监听 + 请求超时双通道判定死亡：在途请求报错，后续调用自动重新拉起，避免僵死连接卡死主流程。
- 六家 AI 提供商怎么统一抽象的？切换提供商「只改一行 YAML」背后的接口设计是什么？
  抽象基类定义 chat / tools / stream 统一接口，配置化模型参数（温度/超时/限流）；子类只实现鉴权与报文差异。提供商+模型名是 YAML 配置项，业务代码只依赖接口，所以切换只改配置。
- 各家模型的 function calling / tool 参数格式差异怎么抹平？
  内部定义统一的工具 schema（zod 描述），提供商适配层各自转换为 OpenAI functions / Gemini functionDeclarations / 智谱等格式，响应再归一化回统一结构——差异收敛在适配层，只写一次。
- 批量处理怎么合并文件元数据以减少 AI 调用次数？免费层限流具体怎么适配？
  把 N 个文件的元数据（文件名/目录/大小/类型）打包成一次请求让模型返回批量分类结果，调用次数从 N 降到 N/batchSize；限流按提供商 RPM/TPM 上限控制并发与重试间隔，批次大小可配置。
- dry-run 模拟执行为什么重要？「AI 误操作不可回滚」你怎么彻底解决？
  AI 分类可能错，批量改名/移动错一次就是灾难。dry-run 先输出完整动作计划供人审，确认后才执行；执行时记录操作日志支持逆向撤销，先验后动 + 可撤销双保险。
- 目录级自定义提示词解决什么问题？优先级怎么和全局配置合并？
  不同目录需要不同命名风格与分类规则（照片按时间、代码按类型）。提示词按目录就近覆盖全局，合并后注入请求，解决「一套提示词管不了整个硬盘」。
- zod 校验 YAML 配置「给出定位错误提示」怎么实现？启动前校验拦下了哪些典型错误？
  schema 定义类型/枚举/范围，parse 失败经 error map 输出字段路径 + 期望值（如 providers[0].models 枚举不命中）。拦下提供商名拼错、超时负数、路径不存在等启动即错，避免运行到一半才暴露。
- 系统代理自动检测在什么网络环境下才需要？手动覆盖通道怎么设计？
  部分提供商域名需要代理才能连通。自动读系统/环境变量代理配置探测可用性，配置可显式指定代理地址或强制直连，覆盖优先级高于自动检测；失败日志明确提示当前生效通道。
- 28 次提交两个月迭代，最大的两次重构是什么？vitest 单测在重构里起了什么作用？
  一是 MCP 协议层从业务代码抽离成独立模块，二是提供商从 if-else 分支重构为基类+适配层。vitest 把协议消息、请求报文写成快照/断言用例，重构时行为回归一秒定位破坏点，敢拆敢改的底气来源。

## 项目亮点挖掘

1. **MCP 客户端自研**
   JSON-RPC 2.0 over stdio 手写协议层：握手协商、工具发现与调用、server 进程生命周期管理，协议细节可控可调。
2. **六提供商统一抽象**
   Groq/Gemini/DeepSeek/Qwen/OpenRouter/智谱 统一客户端接口，切提供商只改一行 YAML，密钥全走环境变量。
3. **成本与安全工程**
   批量合并元数据适配免费层限流；dry-run 先验后动 + 目录级提示词，解决误操作不可回滚与风格不可控。
4. **健壮性底座**
   zod 启动前校验配置并定位报错，代理自动检测 + 手动覆盖双通道，verbose 日志贯穿调用链。
5. **CLI 工程规范**
   commander + @clack/prompts 双交互模式，tsdown 打包，vitest 单测保障重构安全网。
