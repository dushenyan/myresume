## 预测押题

- LoRA 的原理是什么？为什么仅微调约 0.4% 参数就能接近全量效果？
  冻结预训练权重 W，在旁边加低秩旁路 ΔW=BA（rank 远小于隐藏维度）只训 A/B。依据是任务适配的权重更新本身低内在维度，少量参数就能承载足够的领域信号，推理时还可以合并回 W 零延迟开销。
- rank、alpha、target_modules 这些超参怎么调？对效果的影响分别是什么？
  rank 控容量（8/16/32 递增看评估拐点，过大易过拟合）；alpha 是缩放系数常取 2×rank；target_modules 选注入层，先 q/v 注意力层起步，扩到全部线性层换小幅提升换参数量。用评估集网格搜索而非拍脑袋。
- 训练数据和推理解码格式为什么要严格区分？混淆了会出现什么现象？
  训练样本按拼接模板（instruction/input/output 标记）构建成单轮文本，推理时模型接的是 chat 格式。如果拿训练拼接格式去推理，模板对不上会导致模型不识别对话场景、复读训练数据或输出跑偏。
- 双停止符配置指什么？少配一个停止符会发生什么？
  生成时要同时以「单条回答结束符」和「下一轮对话分隔符」作为 eos_token 停止。少配一个，模型会越过本轮结束继续生成下一轮假对话（自问自答式输出），解析层拿到脏数据。
- QLoRA 相比 LoRA 多做了什么？资源受限时量化方案怎么进一步压缩显存？
  QLoRA 把基座权重 4bit（NF4）量化冻结，只训 LoRA 旁路，显存大头（基座）降约 4 倍；配合分页优化器、梯度检查点，单卡消费级显卡就能微调 7B。代价是轻微精度损失，对指令跟随类任务可接受。
- 训练用的基座模型怎么选型？数据集规模和训练轮数怎么定？
  选 Qwen2.5-Instruct：中文能力强、生态工具全、许可友好。数据按目标能力构造千级样本（真实+改写增强），epochs 2-3 轮，以验证集 loss 与任务评估早停，轮数多了反而灾难遗忘。
- 怎么评估微调效果？和直接 Prompt / Few-shot 的大模型比，什么场景下微调才值得？
  固定评估集跑自动指标 + 人工抽检对比基座模型。值得微调的场景：格式/风格一致性要求高、延迟成本敏感要换小模型、私有领域术语 few-shot 带不动；通用能力够用时 prompt 优先，别为调而调。
- 遇到过灾难性遗忘或过拟合吗？怎么发现、怎么处理？
  现象：训完通用问答变笨/复读。发现靠评估集同时含目标任务与通用对照组。处理：降 epochs、降 rank、数据里掺通用指令样本、提高目标层选择性，重新回归验证。

## 项目亮点挖掘

1. **全流程实操**
   Qwen2.5-Instruct LoRA 微调：理论 → 数据准备 → 训练 → 推理调优完整链路走通。
2. **参数高效本质理解**
   掌握「约 0.4% 参数接近全量效果」的低秩适配原理与工程平衡点。
3. **训练/推理一致性**
   严格区分训练与推理解码格式、双停止符配置，规避生成失控的典型坑。
4. **资源受限方案**
   理解 QLoRA 量化在显存受限下如何进一步压缩，具备成本视角的选型判断。
